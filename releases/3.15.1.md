## What this release is about

**Upgrade this one promptly.** It is a security release and nothing else: seven fixes, present in every release up to and including 3.15.0. The most important one meant that a link on another website could make a signed-in analyst empty the ticket trash or change settings without meaning to. Nothing new to learn and nothing to configure. Upgrade and carry on.

## Security

- **A link could change data.** FreeITSM refuses a request from another website that tries to change something, but it only checked the kinds of request a form sends, not the kind a link sends, and about twenty actions could be triggered by a link. Somebody who got a signed-in analyst to click one could empty their company's ticket trash, wipe the SLA settings, clear the public base URL used in email links, or, if the analyst was an administrator, switch module permissions from "least" to "most", blank the branding or run Database Verification. They could not see anything, only cause damage, and each action needed a victim with the right permission. Every action that changes data now refuses a link, and an automated check stops a new one being added. Details: [A link could change data](https://github.com/edmozley/freeitsm/wiki/A-Link-Could-Change-Data).
- **Admin rights outlived a demotion.** An administrator whose rights were removed kept a few administrator-only abilities until they signed out: the Slack settings, approving any catalogue request, editing management lines. A deactivated analyst's open session also kept working on their own account pages. Both are now re-checked on every click, including sessions that are already open. Details: [Admin rights outlived a demotion](https://github.com/edmozley/freeitsm/wiki/Admin-Rights-Outlived-Demotion).
- **Four smaller gaps.** Software inventory API keys could be read by any analyst with the Software module, not just those with the API keys permission. A REST API key limited to one company could create a requester in another company by leaving the company out. The portal's ticket list showed the first line of supplier mail that the privacy setting hides on the ticket itself. A WhatsApp message could be filed on another company's open ticket. Details: [Four smaller gaps](https://github.com/edmozley/freeitsm/wiki/Four-Smaller-Gaps-October-2026).
- **Mailbox sign-in is checked properly.** Connecting a Microsoft 365 or Gmail mailbox now confirms the sign-in was started from FreeITSM, by the analyst who finishes it. A full write-up will follow.

These were reported privately by a security researcher, who asked not to be named. Thank you.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. This release changes nothing in the database, but run it anyway.
3. Hard-refresh your browser (Ctrl-F5).

If you have your own scripts that call FreeITSM's internal endpoints (not the REST API under `/api/v1/`, which is unaffected) and any of them save something with a `GET`, they will now get an error and must use `POST`.

## Rollback

Safe. Nothing was removed from the database, so you can go back to 3.15.0, but going back reopens every issue above.
